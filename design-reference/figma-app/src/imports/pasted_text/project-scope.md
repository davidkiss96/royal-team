1. REMOVE ALL BOOKING / APPOINTMENT FUNCTIONALITY
==================================================

The original design was created when online appointment booking was part of the project.

Booking is NO LONGER part of version 1.

Remove all booking-related UI and concepts throughout the entire website, including:
- "Foglalás"
- "Időpontfoglalás"
- booking buttons
- booking forms
- booking pages
- booking-related sections
- booking CTAs

Replace booking CTAs with contextually appropriate alternatives such as:
- "Szolgáltatásaink"
- "Érdeklődjön"
- "Kapcsolat"
- "Ajánlatkérés"
- "További információ"

Do not simply replace every booking button with the same text. Choose the most appropriate CTA based on the context of each section.

The website should feel complete and intentional without appointment booking.

2. ADD A PRICING / PRICE LIST PAGE
==================================================

Add a dedicated "Árlista" page to the website.

This is an important primary page, not just a small section.

Design:
- premium and highly readable
- easy to scan on desktop and mobile
- consistent with the existing dark/gold visual identity
- suitable for automotive services
- prices should be visually prominent but not overpowering
- organize services into logical categories
- allow room for "Ft-tól" / starting-from pricing
- allow short explanatory notes where needed

Example structure:

ÁRLISTA

[Service category]
Service name                         Price
Service name                         Price
Service name                         Price

[Another category]

Include an appropriate CTA at the bottom leading to the Contact page.

IMPORTANT:
The actual prices are placeholders and will later be managed through Sanity CMS.
The design should therefore support variable service names, prices, price notes and categories.

12. CMS-AWARE DESIGN
==================================================

The website will use Sanity CMS.

Design the content structures so that they can realistically be managed through a CMS.

The following content types will be managed through Sanity:

- Homepage
- Business Settings
- Services
- Projects
- Blog Posts
- Reviews
- Authors

Services, blog posts, projects and reviews should be designed with the assumption that individual entries can be temporarily hidden/unpublished without deleting them.

The design should therefore work naturally whether:
- there are many services/projects/articles
- there are only a few
- some items are temporarily unavailable or hidden

The price list should also be CMS-friendly and support changing prices without redesigning the page.

Do NOT create a generic page-builder or overly complex component system.
